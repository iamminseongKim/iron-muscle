# 3.44.0

## 최신 업데이트 핵심 요약

- AI 처방 템포를 운동 화면과 기록에서 표시합니다. 세트 완료 시 처방 템포를 기본 수행값으로 적용하고 완료 설문에서 다르게 수행한 템포를 수정할 수 있습니다. 원래 처방은 보존하며 자동 적용 출처와 직접 입력 출처를 구분합니다. 자동 적용값을 측정값으로 표현하지 않습니다.
- 종목 교체는 남은 세트의 ID, 순서, 유형, 목표 반복수, RPE, RIR, 휴식, 템포와 메모를 승계합니다. 완료 세트는 원래 종목에 남습니다. 다른 기구의 중량은 참고값으로 보존하고 새 중량을 확인하기 전 시작과 완료를 막습니다.
- 교체 시각과 사유를 저장하고 MD에 내보냅니다. 교체 직후에는 재실행 후에도 되돌릴 수 있습니다. 이후 세트나 운동을 변경하면 최신 기록 보호를 위해 교체 되돌리기를 제공하지 않습니다.
- 템포 편집에서 0초와 취소 후 재열기를 보정했습니다. 재운동과 세트 추가에서 처방을 유지하고 일괄 변경한 목표 중량·반복수·세트 유형을 반영합니다.
- 선택 JSON 필드 `targetRir`, `plannedRepRange` 또는 `repRange`를 지원합니다. 알 수 없는 필드는 미리보기에서 미적용 항목으로 안내합니다. 잘못된 지원 필드는 가져오기를 거부합니다. 새 문구는 8개 언어에 반영했습니다.

## 데이터 및 JSON 호환성

기존 `title`, `exercises`, `name` 형식과 3단계 템포 객체를 유지합니다. 각 단계는 0~30초입니다. `pause`는 기존 정지 구간이며 상단 정지는 별도 지원하지 않습니다. `3-1-1-0` 문자열은 지원 형식으로 추정하지 않고 거부합니다.

```json
{
  "title": "Tempo example",
  "exercises": [{
    "name": "Lat Pulldown",
    "tempo": { "eccentric": 3, "pause": 1, "concentric": 1 },
    "targetRir": 2,
    "repRange": { "min": 8, "max": 12 },
    "sets": [{ "reps": 10, "weight": 20, "setType": "WORKING", "targetRpe": 8 }]
  }]
}
```

DB 구조 변경이나 기록 삭제 마이그레이션은 없습니다. 기존 localStorage 기록에 선택 필드를 추가합니다. 실제 RPE, 휴식, 보조 반복수는 입력 또는 측정하지 않으면 미기록으로 남습니다. `tempoSource=prescribed`는 처방에서 적용한 수행 기본값이며 `recorded`는 직접 입력값입니다.

## 검증

- `npm test` 전체 31개 테스트 묶음과 `npm run build`의 TypeScript·웹 빌드·모델 검증·오프라인 셸 생성이 통과했습니다. 기존 큰 청크 경고는 남아 있습니다.
- 사용자 제공 6종목 20세트 샘플을 재현 가능한 fixture로 보존했습니다. 템포 기본 적용과 명시적 수정, 완료 세트 귀속, 중량 확인, 재시작, 중복 완료 방지, 백업과 8개 언어 MD를 검사합니다.
- 실제 Chrome 모바일 화면에서 `test-prescribed-tempo-ui`, `test-prescription-survey-ui`, `test-prescription-replacement-ui`가 통과했습니다. 템포 표시·편집·0초·취소·중량 확인·설문 완료·교체·새로고침 후 되돌리기를 검증했습니다.

## 한계

- 실제 Android 기기에서 확인하지 않았습니다.
- 샘플의 일부 운동명은 카탈로그의 정확한 이름과 일치하지 않아 선택 또는 신규 등록이 필요합니다. 앱은 불확실한 종목을 자동 지정하지 않습니다.
- 처방 템포 자동 적용은 센서 측정이 아닙니다. 수행 템포를 직접 측정하지 않습니다.
- 동일 JSON을 새 운동으로 다시 시작하면 새로운 세션을 생성하는 기존 동작을 유지합니다. Import 미리보기와 종목 교체 재시도로 세트가 추가되지는 않습니다.
